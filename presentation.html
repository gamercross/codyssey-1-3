Architecture Overview

시스템 구조 및 핵심 설계 원칙

순수 파이썬 표준 라이브러리로 완성도 높은 2차원 정사각 행렬 구조와 에러 복원 파이프라인을 설계했습니다.

▦
Matrix 추상화 & 검증
  • `Matrix` 클래스: N×N 2차원 정사각 배열 래퍼
  • 위치별 get(r, c) / set(r, c, v) 추상화
  • from_rows()를 통한 엄격한 유효성 검사
    • 행/열 길이 일치 여부
    • 정수/실수 타입 확인 (bool 제외)
    • 기대 크기 일치성 보장
⚡
MAC 연산 엔진
  • mac(pattern, flt): 같은 위치끼리 곱해 누적하는 $N^2$ 번의 반복 연산
  • 내부 리스트 직접 캐싱(p_rows[i])으로 인덱싱 오버헤드 최소화
  • 디버깅 모드: verbose=True 활성화 시 단계별 곱셈 누적값 실시간 추적 지원
🛡
라벨 정규화 & 동점 방어
  • normalize_label() 분리로 '+', 'cross', 'x' 등의 이기종 라벨을 표준 Cross / X로 단일화
  • 부동소수점 오차 완화를 위한 EPSILON = 1e-9 기반 동점 검출
  • 동점 발생 시 안전한 UNDECIDED 처리 규칙 확립
💡 단일 책임 원칙(SRP) 준수: 라벨 변환 로직을 판정 엔진에서 분리함으로써, 추후 Triangle 등 새로운 기하 라벨이 추가되더라도 기존 판정 수식 수정 없이 사전 테이블 확장만으로 대응 가능합니다.

Mathematical Principle

MAC 연산과 형태 유사도 판정 메커니즘

패턴 행렬과 필터 행렬의 내적(Dot Product)을 통해 직관적이고 강력한 기하학적 유사도를 도출합니다.

MAC 연산 원리 수식
Score = ∑_{i=0}^{N-1} ∑_{j=0}^{N-1} Pattern[i][j] × Filter[i][j]
  • 십자가(Cross) 필터: 가로/세로 중앙 행/열이 1 (총 2N - 1 칸)
  • X 필터: 주대각선 및 반대각선이 1 (총 2N - 1 칸)
  • 두 필터의 교집합: N이 홀수일 때 정중앙 단 1칸만 일치 (1 칸)
📈 점수 격차 분석: 일치하는 필터는 점수 $2N - 1$을 획득하지만, 불일치하는 필터는 단 1점에 그쳐 N이 커질수록 판정 신뢰도가 기하급수적으로 높아집니다.

복잡도 및 NPU 가속의 필요성
  • 시간 복잡도: $N \times N$ 모든 원소를 순회하므로 **$O(N^2)$**이며, 총 입력 원소 수 $M = N^2$ 기준으로는 **$O(M)$** 선형 시간입니다.
  • 고정 비용(Fixed Overhead) 효과: 3×3 등 소형 크기에서는 파이썬 함수 호출 비용이 차지하는 비중이 크나, $N$이 커질수록 칸당 연산 시간이 약 25 ns로 일정하게 수렴합니다.
  • 대형 N(1000×1000) 비용 분석:
    • $M = 1,000,000$ 셀 (단일 행렬 약 8MB 메모리)
    • CPU 순차 연산 시 1회 MAC에 25~30ms 소요
    • 128개 채널 합성 시 프레임당 약 3.5초 소요 (실시간 처리 불가)
🚀 NPU의 병렬성: Systolic Array 구조를 통해 수천 개의 MAC 연산기를 하드웨어적으로 병렬 배치하여 $O(N^2)$의 연산 지연을 획기적으로 압축합니다.

Rubric 2 · Code Structure

⚡
MAC 흐름: 입력 → 곱셈 → 누적 → 점수
입력 → Matrix.from_rows() 검증
mac(pattern, filter):
  total = 0.0
  for i, for j:
    total += p[i][j] * f[i][j]
  return total → decide()가 epsilon 비교
mac()은 입출력을 모르고 행렬 둘 → 숫자 하나만 돌려줍니다. 모드 1·2·3과 성능 측정이 모두 같은 함수를 재사용합니다.
🔑
패턴 키 → 크기 N → 필터 매칭
  • size_5_2를 ^size_(\d+)_(\d+)$로 읽어 N=5. 형식이 다르면 MAC 전에 "키 형식 오류"로 FAIL
  • 필터는 로드 때 {5: {Cross, X}, 13: {...}} 처럼 크기를 키로 하는 딕셔너리로 저장 → filters.get(N) 한 번으로 선택
  • 필터 없음 · 패턴 실제 크기 불일치는 각각 FAIL 처리 (IndexError로 멈추지 않음)
  • 키 이름의 N과 실제 배열 크기를 대조: 둘 중 하나만 믿으면 데이터가 어긋날 때 조용히 틀립니다
🏷
normalize_label()을 분리한 이유와 장점
  • 이유: 데이터는 '+'/'x', 'cross'/'x'를 섞어 씁니다. 그대로 비교하면 로직이 맞아도 전부 FAIL
  • 표기 흡수를 LABEL_ALIASES 표 + 함수 하나로 모으고, 내부에서는 Cross/X만 사용
  • 장점: 판정·출력 코드가 표기를 모름 · 대소문자/공백 처리 한 곳 · 모르는 표기는 None → "데이터 오류"와 "로직 오류"가 섞이지 않음 · 새 라벨은 표에 한 줄 추가

Rubric 3 · Core Principles

평가문항 3 · 핵심 기술 원리 적용

점수의 의미, O(N²), 부동소수점 오차, 모드별 동점 규칙을 요구사항 관점에서 설명합니다.

∑
MAC 점수가 높을수록 더 닮은 이유
  • MAC은 두 배열의 내적. 필터가 1인 자리에 패턴도 1이면 곱이 점수에 더해지고, 한쪽이 0이면 더해지지 않음
  • 점수 = "필터가 표시한 칸 중 패턴이 같이 켜진 칸의 수". 겹침이 많을수록 높음
  • 이 데이터: 맞는 필터 2N−1, 틀린 필터 1 (가운데 한 칸만 겹침)
  • 한계: 전부 1인 패턴은 어느 필터와도 높게 나옴 → 이 과제는 두 필터의 상대 비교이므로 충분
N²
연산 횟수 N² → O(N²) 경향
  • N×N 칸을 한 번씩 곱하고 더하므로 곱셈 N², 덧셈 N² → O(N²)
  • 5×5 → 25×25: N은 5배, 연산 횟수는 25배, 시간은 0.0011 → 0.0168 ms (약 15배)
  • 작은 크기는 함수 호출 같은 고정 비용 때문에 배율이 낮고, 칸당 시간이 약 25 ns로 수렴 → N² 비례의 증거
ε
부동소수점 오차와 epsilon 정책
  • 실수는 2진수로 저장되고 0.1은 딱 떨어지지 않아 0.1 + 0.2 = 0.30000000000000004
  • ==는 진짜 동점을 한쪽 승리로 오판, >만 쓰면 1e-17 오차가 판정을 뒤집음
  • 그래서 |a − b| < 1e-9면 "사실상 같다"로 먼저 걸러냄. 1e-9는 float64 오차(1e-16대)보다 크고 의미 있는 점수 차이(정수 1 이상)보다 훨씬 작음

1K
1000×1000 패턴을 처리한다면
  • 시간: MAC 1회 = 10⁶ 연산. 칸당 약 25 ns 적용 시 약 25 ms (필터 2개면 50 ms), 수천 장이면 분 단위. 병목은 Python 반복문
  • 메모리: 리스트 + float 객체로 칸당 약 32 B → 패턴 하나 약 30 MB, 필터 2개 포함 약 100 MB

  1. array('d') / NumPy 내적 (효과 최대, 칸당 8 B)
  2. 필터를 1인 칸 좌표만 저장 (십자가는 2N−1칸 → O(N))
  3. 1차원 연속 배열 (이 과제 측정에서는 효과 작음)

🧠
CPU 직렬 vs NPU 병렬: 병목은 어디에
  • CPU: 곱셈 · 덧셈을 한 칸씩 순서대로 → N² 번이 시간에 그대로 더해짐
  • NPU: N²개의 곱셈은 서로 의존성이 없어 MAC 유닛 수천 개가 동시에 곱하고 누산기에서 합산
  • 병렬화하면 연산은 빨라지지만 병목이 메모리 대역폭(데이터 이동)으로 옮겨 감. 곱셈기는 놀고 값이 도착하지 않는 상태
  • 대응: 온칩 메모리에 필터를 두고 재사용(weight stationary), INT8 등 낮은 정밀도로 이동량 축소
이 프로그램의 병목은 "Python 반복 N²". 규모가 커지면 "곱셈 개수"에서 "값을 가져오는 속도"로 이동합니다.
